# Architecture

How the packages under `utama_core/` depend on each other, and how one tick flows through them.

## One tick

The flow of one tick of `StrategyRunner`, from vision to robot (module paths under `utama_core/`; the
same steps in words: [README](../README.md#system-design)). [pipeline_method.md](pipeline_method.md)
describes the same path in more detail.

```mermaid
flowchart TD
    subgraph input["Input"]
        vis["Vision frames<br/>data_processing/receivers/vision_receiver.py (real, grSim)<br/>or rsim observations"]
        refsrc["Referee data<br/>referee/custom_referee.py (rsim)<br/>or data_processing/receivers/referee_receiver.py"]
    end

    subgraph world["World model (data_processing/refiners/)"]
        pos["PositionRefiner<br/>refiners/position.py"]
        vel["VelocityRefiner<br/>refiners/velocity.py"]
        rinfo["RobotInfoRefiner<br/>refiners/robot_info.py"]
        rref["RefereeRefiner<br/>refiners/referee.py"]
        game["Game / GameFrame<br/>entities/game/game.py"]
    end

    subgraph decision["Decision (engine/, strategy/)"]
        strat["Strategy.tick<br/>engine/strategy.py"]
        restart{"Restart, STOP or TIMEOUT?<br/>engine/referee_override.py"}
        halt{"HALT?<br/>engine/referee_reset.py"}
        ovr["RefereeOverride.tick<br/>engine/referee_override.py<br/>referee/actions.py"]
        part["Partitioner (robots per tactic)<br/>engine/strategy.py, strategy/*.py"]
        tac["Tactic.tick<br/>tactics/*.py"]
        skill["Skills<br/>skills/*.py"]
    end

    subgraph motion["Motion (motion_planning/)"]
        mc["MotionController.calculate<br/>motion_planning/controllers/<br/>fpp, dwa, trajsample"]
    end

    subgraph output["Output (team_controller/)"]
        ctrl["RobotController.send_robot_commands<br/>team_controller/controllers/"]
        rsim["rsim<br/>rsoccer_simulator/ (sim/rsim_robot_controller.py)"]
        grsim["grSim over UDP<br/>sim/grsim_robot_controller.py"]
        real["Real robots over radio<br/>real/real_robot_controller.py"]
    end

    vis --> pos
    pos --> vel --> rinfo --> rref
    refsrc --> rref
    rref --> game
    game --> strat
    game -. "previous frame" .-> refsrc
    strat --> restart
    restart -- "yes" --> ovr
    restart -- "no" --> halt
    halt -- "yes: no tactic commands" --> ctrl
    halt -- "no" --> part
    part --> tac --> skill --> mc
    ovr --> mc
    mc --> ctrl
    ctrl --> rsim
    ctrl --> grsim
    ctrl --> real
```

## Match data flow

Every rsim match writes files under `replays/` (`REPLAY_BASE_PATH`), and the analyses, tools and
evaluation read them back. A match's file stem is `A_vs_B` (`evaluate.py`'s `tag`); the names
below are from a real run directory. The match results store (`replays/match_results/`) is read first:
a match it holds is not played again, so only matches whose fingerprint changed are played.

![Match data flow: drivers, StrategyRunner, the per-match files, the stores and the readers](img/architecture/match_data_flow.png)

Drawn by `docs/img/architecture/make_match_data_flow.py`; rerun it when a name in it changes.

`evaluate.py` removes its own scratch run directory when it finishes, so its matches survive only
in the match results store.

excluded as sources). Each edge is one first-level package importing another, labelled with its
number of imports; packages with no edges are left out. Regenerate and paste the output below:

    pixi run python tools/dev/package_graph.py

The only edge into `tests` is `run` (the runner imports `utama_core/tests/common`'s test manager).
