│ Custom Referee System — Implementation Plan                                  │
│                                                                              │
│ Context                                                                      │
│                                                                              │
│ The project already has a RefereeMessageReceiver that listens for the        │
│ official AutoReferee's UDP multicast. This works in Real and grSim modes but │
│  not RSim (no AutoReferee process is running there). The existing            │
│ RefereeStateMachine in rsoccer_simulator/ only detects goals and operates on │
│  raw Frame objects from the C++ simulator — it is tied to RSim.              │
│                                                                              │
│ The goal is a CustomReferee that:                                            │
│ - Operates on the already-refined GameFrame (post-position/velocity          │
│ refiners) — the same data strategies use                                     │
│ - Works uniformly across all 3 modes (Real, grSim, RSim)                     │
│ - Replaces or supplements RefereeMessageReceiver as the ref_buffer source    │
│ - Supports configurable game profiles (Strict AI, Exhibition, Arcade) via    │
│ YAML                                                                         │
│ - Uses configurable field geometry so small/custom physical fields don't     │
│ break anything                                                               │
│                                                                              │
│ The downstream pipeline (RefereeRefiner → GameFrame.referee → behaviour tree │
│  CheckRefereeCommand nodes) is unchanged.                                    │
│                                                                              │

│ Step 1 — geometry.py: RefereeGeometry                                        │
│                                                                              │
│ A frozen dataclass with runtime-configurable field dimensions. Completely    │
│ independent from Field — does not modify it. The Field class constants       │
│ remain untouched.                                                            │
│                                                                              │
│ @dataclass(frozen=True)                                                      │
│ class RefereeGeometry:                                                       │
│     half_length: float           # default: 4.5 (=                           │
│ Field._FULL_FIELD_HALF_LENGTH)                                               │
│     half_width: float            # default: 3.0 (=                           │
│ Field._FULL_FIELD_HALF_WIDTH)                                                │
│     half_goal_width: float       # default: 0.5 (= Field._HALF_GOAL_WIDTH)   │
│     half_defense_length: float   # default: 0.5 (=                           │
│ Field._HALF_DEFENSE_AREA_LENGTH)                                             │
│     half_defense_width: float    # default: 1.0 (=                           │
│ Field._HALF_DEFENSE_AREA_WIDTH)                                              │
│     center_circle_radius: float  # default: 0.5                              │
│                                                                              │
│ Methods to add:                                                              │
│ - from_standard_div_b() classmethod — returns geometry matching Field        │
│ constants exactly                                                            │
│ - from_field_bounds(field_bounds: FieldBounds) classmethod — derives         │
│ half_length/width from a FieldBounds, uses Field class constants for         │
│ goal/defense sizes                                                           │
│ - is_in_field(x, y) -> bool                                                  │
│ - is_in_left_goal(x, y) -> bool / is_in_right_goal(x, y) -> bool             │
│ - is_in_left_defense_area(x, y) -> bool / is_in_right_defense_area(x, y) ->  │
│ bool                                                                         │
│                                                                              │
│ Key file to reference: utama_core/entities/game/field.py — mirror its        │
│ constants in from_standard_div_b().                                          │
│                                                                              │

│ Step 3 — rules/: Modular rule checkers                                       │
│                                                                              │
│ base_rule.py:                                                                │
│ @dataclass(frozen=True)                                                      │
│ class RuleViolation:                                                         │
│     rule_name: str                                                           │
│     suggested_command: RefereeCommand   # e.g. STOP                          │
│     next_command: Optional[RefereeCommand]  # e.g. DIRECT_FREE_YELLOW        │
│     status_message: str                                                      │
│     designated_position: Optional[tuple[float, float]] = None                │
│                                                                              │
│ class BaseRule(ABC):                                                         │
│     @abstractmethod                                                          │
│     def check(self, game_frame: GameFrame, geometry: RefereeGeometry,        │
│               current_command: RefereeCommand) -> Optional[RuleViolation]:   │
│ ...                                                                          │
│     def reset(self) -> None: pass  # called on command transition            │
│                                                                              │
│ goal_rule.py — GoalRule:                                                     │
│ - Checks ball.p.x > geometry.half_length and abs(ball.p.y) <                 │
│ geometry.half_goal_width (right goal = yellow scored) and vice versa for     │
│ left goal                                                                    │
│ - Has _last_goal_time: float for cooldown (from profile cooldown_seconds)    │
│ - Returns RuleViolation(suggested_command=STOP,                              │
│ next_command=PREPARE_KICKOFF_<other_team>, status_message="Goal by X")       │
│ - Note: score increment happens in GameStateMachine, not here                │
│                                                                              │
│ out_of_bounds_rule.py — OutOfBoundsRule:                                     │
│ - Fires when abs(ball.p.x) > geometry.half_length (but not in goal) or       │
│ abs(ball.p.y) > geometry.half_width                                          │
│ - Reads game_frame to determine last-touching team (robot that had           │
│ has_ball=True most recently, tracked via robot proximity to ball if has_ball │
│  is unavailable for enemies)                                                 │
│ - Returns DIRECT_FREE_<non-touching-team> with designated_position = nearest │
│  touchline point, offset 0.1 m infield                                       │
│                                                                              │
│ defense_area_rule.py — DefenseAreaRule:                                      │
│ - Only active during NORMAL_START / FORCE_START (guard on current_command)   │
│ - Checks each robot in game_frame.enemy_robots against                       │
│ geometry.is_in_my_defense_area() (resolves based on                          │
│ game_frame.my_team_is_right)                                                 │
│ - Returns DIRECT_FREE_<defending_team> on attacker entry                     │
│ - Also checks if >max_defenders friendly robots are in own defense area      │
│                                                                              │
│ keep_out_rule.py — KeepOutRule:                                              │
│ - Only active during STOP or DIRECT_FREE_* commands                          │
│ - Checks distance of non-kicking-team robots to ball.p                       │
│ - Has _violation_frame_count: int for persistence debounce (avoids false     │
│ positives from transient positions)                                          │
│ - Returns DIRECT_FREE_<other_team> after violation_persistence_frames        │
│ consecutive violations                                                       │
│                                                                              │
│ ---                                                                          │
│ Step 4 — state_machine.py: GameStateMachine                                  │
│                                                                              │
│ Owns all mutable game state. Heavily inspired by the existing                │
│ RefereeStateMachine in rsoccer_simulator/src/ssl/referee_state_machine.py    │
│ but operates at a higher abstraction level.                                  │
│                                                                              │
│ State fields:                                                                │
│ - command: RefereeCommand, command_counter: int, command_timestamp: float    │
│ - stage: Stage, stage_start_time: float, stage_duration: float               │
│ - yellow_team: TeamInfo, blue_team: TeamInfo (mutable, use                   │
│ TeamInfo.increment_score())                                                  │
│ - next_command: Optional[RefereeCommand]                                     │
│ - ball_placement_target: Optional[tuple[float, float]]                       │
│ - _transition_cooldown_seconds: float = 0.3 — prevents command oscillation   │
│                                                                              │
│ Key method:                                                                  │
│ def step(self, current_time: float, violation: Optional[RuleViolation]) ->   │
│ RefereeData:                                                                 │
│     """Process one tick. Apply violation if not in cooldown. Return          │
│ RefereeData."""                                                              │
│                                                                              │
│ Transition logic:                                                            │
│ - GoalViolation during NORMAL_START/FORCE_START → increment score on correct │
│  TeamInfo, set command = STOP, next_command = PREPARE_KICKOFF_<other_team>,  │
│ set cooldown                                                                 │
│ - OutOfBoundsViolation during NORMAL_START/FORCE_START → STOP, next_command  │
│ = DIRECT_FREE_*, store designated_position                                   │
│ - DefenseAreaViolation during NORMAL_START/FORCE_START → STOP, next_command  │
│ = DIRECT_FREE_*                                                              │
│ - When in STOP and violation carries a PREPARE_KICKOFF_* as next_command,    │
│ surface it via RefereeData.next_command to let the AI pre-position           │
│                                                                              │
│ The state machine does not auto-advance from STOP to NORMAL_START — that     │
│ transition remains manual (operator clicks NORMAL_START, or in future a GUI  │
│ sends it). This keeps control explicit. For RSim/RL training, the caller can │
│  call state_machine.set_command(NORMAL_START) after a fixed delay.           │
│                                                                              │
│ Uses RefereeData._replace() pattern as seen in                               │
│ RefereeStateMachine._generate_referee_data().                                │
│                                                                              │
│ ---                                                                          │
│ Step 5 — custom_referee.py: CustomReferee                                    │
│                                                                              │
│ class CustomReferee:                                                         │
│     def __init__(self, profile: RefereeProfile):                             │
│         self._geometry = profile.geometry                                    │
│         self._rules: list[BaseRule] = _build_active_rules(profile.rules)     │
│         self._state = GameStateMachine(profile, n_robots_yellow=...,         │
│ n_robots_blue=...)                                                           │
│                                                                              │
│     @classmethod                                                             │
│     def from_profile_name(cls, name: str, **kwargs) -> "CustomReferee": ...  │
│                                                                              │
│     def step(self, game_frame: GameFrame, current_time: float) ->            │
│ RefereeData:                                                                 │
│         violation = None                                                     │
│         for rule in self._rules:                                             │
│             result = rule.check(game_frame, self._geometry,                  │
│ self._state.command)                                                         │
│             if result is not None:                                           │
│                 violation = result                                           │
│                 break  # first match wins; list is ordered by priority       │
│         return self._state.step(current_time, violation)                     │
│                                                                              │
│     def set_command(self, command: RefereeCommand, timestamp: float) ->      │
│ None:                                                                        │
│         """Manual override — for operator use or test scripting."""          │
│         self._state.set_command(command, timestamp)                          │
│                                                                              │
│ Rule priority order in _build_active_rules: GoalRule → OutOfBoundsRule →     │
│ DefenseAreaRule → KeepOutRule.                                               │
│                                                                              │

● Found it. The bug is in goal_rule.py — the comments and team assignments are
  wrong. The GoalRule doesn't receive game_frame.my_team_is_right, so it
  hardcodes an assumption about which team defends which goal. The comment says
  "blue defends right" but in the demo my_team_is_right=True means yellow
  defends the right goal — so a ball in the right goal means blue scored, not
  yellow.

  The rule needs my_team_is_right from the GameFrame to correctly assign scorer
  vs defender. Here's the correct logic:

  - Ball in right goal (x > half_length) → right-side team conceded → left-side 
  team scored
  - Ball in left goal (x < -half_length) → left-side team conceded → right-side 
  team scored
  - my_team_is_right=True → yellow is on the right, blue is on the left
    - Right goal → yellow conceded → blue scored → kickoff for yellow
    - Left goal → blue conceded → yellow scored → kickoff for blue

       96 +    DIRECT_FREE_BLUE --> NORMAL_START : set_command()

      101 +                                                              
      102 +> **Key design principle:** `CustomReferee` only ever *moves i
          +nto* `STOP` automatically. All transitions *out of* `STOP` req

          +n operator interacts with a real game controller.             
      103 +                                                              
      104 +### Transition cooldown                                       
      105 +                                                              
      106 +A 0.3 s cooldown (`_TRANSITION_COOLDOWN`) prevents the same vi
          +olation from being applied multiple times in quick succession 
          +(e.g., the ball briefly in the goal for several frames).

      109 +                                                              
      110 +## Rule Checkers                                              
      111 +                                                              
      112 +Each rule is a `BaseRule` subclass. Rules are evaluated in pri
          +ority order; the **first match wins** and subsequent rules are
          + skipped for that tick.                                       
      113 +                                                              
      114 +### Priority order                                            
      115 +                                                              
      116 +| Priority | Rule | Active during |                           
      117 +|----------|------|---------------|                           
      118 +| 1 | `GoalRule` | `NORMAL_START`, `FORCE_START` |            
      119 +| 2 | `OutOfBoundsRule` | `NORMAL_START`, `FORCE_START` |     
      120 +| 3 | `DefenseAreaRule` | `NORMAL_START`, `FORCE_START` |     
      121 +| 4 | `KeepOutRule` | `STOP`, `DIRECT_FREE_*`, `PREPARE_KICKOF
          +F_*`, `PREPARE_PENALTY_*` |                                   
      122 +                                                              
      123 +### GoalRule                                                  
      124 +                                                              
      125 +Detects when the ball crosses the goal line within the goal po
          +sts. Uses `game_frame.my_team_is_right` and `game_frame.my_tea
          +m_is_yellow` to determine which team scored — not a hardcoded 
          +assignment.                                                   
      126 +                                                              
      127 +```                                                           
      128 +yellow_is_right = (my_team_is_right == my_team_is_yellow)     
      129 +                                                              
      130 +ball in right goal:                                           
      131 +    yellow_is_right=True  → blue scored  → PREPARE_KICKOFF_YEL
          +LOW                                                           
      132 +    yellow_is_right=False → yellow scored → PREPARE_KICKOFF_BL
          +UE                                                            
      133 +                                                              
      134 +ball in left goal:                                            
      135 +    yellow_is_right=True  → yellow scored → PREPARE_KICKOFF_BL
          +UE                                                            
      136 +    yellow_is_right=False → blue scored   → PREPARE_KICKOFF_YE
          +LLOW                                                          
      137 +```                                                           
      138 +                                                              
      139 +A configurable `cooldown_seconds` (default 1.0 s) prevents dup
          +licate detections while the ball sits past the goal line for m
          +ultiple frames.                                               
      140 +                                                              
      141 +### OutOfBoundsRule                                           
      142 +                                                              
      143 +Fires when `abs(ball.p.x) > half_length` (not in a goal) or `a
          +bs(ball.p.y) > half_width`. Tracks last-touch by:             
      144 +1. Checking `robot.has_ball` (reliable IR sensor on friendly r
          +obots).                                                       
      145 +2. Falling back to the closest robot within 0.15 m.           
      146 +                                                              
      147 +The non-touching team receives the `DIRECT_FREE_*`. The `desig
          +nated_position` is placed 0.1 m infield from the nearest bound
          +ary point.                                                    
      148 +                                                              
      149 +### DefenseAreaRule                                           
      150 +                                                              
      151 +Only active during `NORMAL_START` and `FORCE_START`. Checks tw
          +o conditions:                                                 
      152 +                                                              
      153 +- **Too many defenders:** more than `max_defenders` (default 1
          +) friendly robots inside their own defence area → opponent get
          +s `DIRECT_FREE_*`.                                            
      154 +- **Attacker infringement:** any enemy robot inside the friend
          +ly team's defence area → friendly team gets `DIRECT_FREE_*`.  
      155 +                                                              
      156 +Uses `game_frame.my_team_is_right` to resolve which geometry h
          +elper (`is_in_left/right_defense_area`) corresponds to "my" go
          +al.                                                           
      157 +                                                              
      158 +### KeepOutRule                                               
      159 +                                                              
      160 +Only active during stoppages (`STOP`, `DIRECT_FREE_*`, `PREPAR
          +E_KICKOFF_*`, `PREPARE_PENALTY_*`). Checks that non-kicking-te
          +am robots stay outside a configurable `radius_meters` (default
          + 0.5 m) from the ball.                                        
      161 +                                                              
      162 +Uses a persistence counter: a violation is only issued after `
          +violation_persistence_frames` (default 30, ≈ 0.5 s at 60 Hz) *
          +*consecutive** frames of encroachment. This avoids false posit
          +ives from robots passing through the zone.

● Looking at the implementation against the plan and the existing
  referee_integration.md, here's what's incomplete or missing:

  ---
  Functional gaps

  1. No auto-advance out of STOP

  After a goal or foul, the state machine issues STOP and waits forever. In
  RSim/RL training there is no human operator to click "resume". The caller has
  to manually call set_command(NORMAL_START) after a fixed delay — but there is
  no helper for this. A force_start_after_goal flag exists in the profile and is
   stored, but never used.

  2. force_start_after_goal is stored but ignored

  CustomReferee.__init__ sets self._force_start_after_goal = 
  profile.game.force_start_after_goal but step() never checks it. The arcade
  profile sets this to true, but the behaviour is identical to strict_ai.

  3. KeepOutRule awards free kick to the wrong team on STOP

  When current_command == STOP (no kicking team), _kicking_team_is_yellow
  returns None and the rule awards DIRECT_FREE_YELLOW unconditionally. It should
   award the free kick based on who was last fouled or use next_command from the
   state machine as context.

  4. Double-touch rule is never implemented

  DoubleTouchConfig exists in the profile schema and YAML files, but there is no
   DoubleTouchRule class. It is silently ignored by _build_active_rules.

  5. Ball speed rule is never implemented

  Same situation — BallSpeedConfig is in the schema but no BallSpeedRule exists.

  ---
  Integration gaps

  6. my_current_game_frame is one frame stale in StrategyRunner

  The plan acknowledges this is acceptable, but it means a goal scored at tick N
   is only detected at tick N+1. For high-speed RL training this is fine; for
  real/grSim it could be worth documenting explicitly or fixing.

  7. No way to reset the score between episodes

  In RL training, each episode starts with a fresh StrategyRunner which
  constructs a new CustomReferee. But if CustomReferee is reused across
  episodes, the score carries over. There is no reset() method on CustomReferee
  or GameStateMachine.

  8. OutOfBoundsRule doesn't track last touch across the boundary moment

  The proximity fallback (closest robot within 0.15 m) only updates when the
  ball is still in bounds. The moment the ball exits, _last_touch_was_friendly
  may still be None if no robot was close enough, defaulting to yellow — which
  is arbitrary.

  ---
  Missing tests

  9. Goal assignment for blue team (my_team_is_yellow=False) is untested

  The three goal tests all use my_team_is_yellow=True. There is no test for when
   the calling perspective is the blue team, so the yellow_is_right
  calculation's blue-perspective branch is unverified.

  10. No integration test for StrategyRunner with custom_referee

  The unit tests cover the referee in isolation. There is no test that
  constructs a StrategyRunner(custom_referee=..., mode="rsim") and verifies the
  RefereeData flows through to game_frame.referee.
